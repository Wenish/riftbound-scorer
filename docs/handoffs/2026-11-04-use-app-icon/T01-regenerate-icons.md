- **Plan:** [PLAN.md](./PLAN.md)

## Brief

### Goal

Replace all default/old app icons with ones generated from the master icon `src-tauri/app-icon.png`
(1024×1024, opaque, source `src-tauri/app-icon.svg`), for both the Tauri app and the PWA.

### Scope

- `src-tauri/icons/**` — regenerate with `npm run tauri icon` (its default input is `src-tauri/app-icon.png`;
  pass the path explicitly to be safe). Keep the generated set the CLI produces (incl. `android/`/`ios/`
  subfolders if it creates them) — these are used once the mobile targets are initialised.
- `src-tauri/tauri.conf.json` — only if `bundle.icon` must change to match the generated files (likely not).
- `package.json` — change the `generate-pwa-assets` script to copy `src-tauri/app-icon.png` (instead of
  `src-tauri/icons/icon.png`) to `public/pwa-source.png`, then run the generator and clean up as today.
- `pwa-assets.config.ts` — update its header comment to the new source path; keep the preset/background logic.
- `public/*` — regenerated by `npm run generate-pwa-assets` (favicon.ico, pwa-64/192/512, maskable-512,
  apple-touch-180). Make sure `public/pwa-source.png` is not left behind.
- `README.md` — if it documents icon generation, update it; otherwise add a short "App icon" note under the
  dev commands: edit `src-tauri/app-icon.svg`, re-render the PNG, run `npm run tauri icon src-tauri/app-icon.png`
  and `npm run generate-pwa-assets`. Keep it brief and in the README's existing style.

### Out of scope

- Do not edit `src-tauri/app-icon.svg` / `.png` (the artwork is final).
- No changes to app code (`src/`), service worker logic, or manifest fields other than icon entries if
  file names change.
- No new npm dependencies.

### Context to read

- `pwa-assets.config.ts`, `package.json` scripts, `vite.config.ts` (manifest `icons`), `index.html` (icon links),
  `src-tauri/tauri.conf.json` (`bundle.icon`), `README.md`.
- `docs/handoffs/2026-11-04-pwa-setup/T01-plugin-manifest-icons.md` — how the PWA icons were set up.

### Acceptance criteria

- [ ] `src-tauri/icons/icon.png`, `32x32.png`, `128x128.png`, `128x128@2x.png`, `icon.icns`, `icon.ico` and
      the Square*/StoreLogo PNGs are regenerated from the master (look at a couple of them, e.g. `icon.png` and `32x32.png`).

- [ ] No leftover `public/pwa-source.png`; no stray files outside the scope above (`git status --short`).
- [ ] `npm run build` succeeds and `dist/` contains the new icons + `manifest.webmanifest` referencing them.
- [ ] Grep the repo (excluding `node_modules`, `dist`, `src-tauri/target`) for leftover references to
      default Vite/Tauri/Vue logos (`vite.svg`, `tauri.svg`, `vue.svg`) and report them; remove any that are wired into the app.

However, the launcher mask shows only the central about 66% (72dp of 108dp). The dashed ring spans about 77% of the foreground, so its outer edge will be slightly clipped by circular launcher masks. The crystal is not affected. If that matters, re-run `tauri icon` with a manifest JSON: `default` set to `app-icon.png`, `android_fg_scale` set lower, and `bg_color` set close to the master edge colour (`#03071a`). I did not do this because the brief says to use the CLI defaults.

The emblem is inside the safe zone. Fixing the seam would mean changing the padding or background logic in `pwa-assets.config.ts`, which the brief says to keep. One option is less padding for the maskable icon, because the emblem already fits the 80% safe circle at about 76%.
- `pwa-*.png` keep the `minimal-2023` preset's transparent margin around the square artwork, the same behaviour as before.
